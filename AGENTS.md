# LentoTech website maintenance — required instructions for AI tools

The authoritative production branch is `codex/unified-website`, not `main`. The Cloudflare Pages project `lentotech-stage` serves `https://lentotech.com` and `https://www.lentotech.com` using `node build.mjs` and `dist/`. Read the current README and inspect the current branch and working-tree changes before making any changes. PR #3 integrated the trade catalog; the obsolete main-based PR #2 was closed without merging.

- Work only within the user's authorized scope, fetch the actual production baseline, and preserve existing content, product IDs, detail URLs, search, navigation, language support, sitemap, SEO/GEO (`llms.txt`), shared styles and the current native inquiry form with private feedback and email fallback. Never replace the current site with older static `main` content or modify generated `dist/` as source.
- Native managed products, news, company and service content belong in the corresponding existing `content.json` records and authorized management page; preserve IDs, source references and dates. Trade workbench products are delivered only through the approved `trade-catalog.json` public feed. Preserve original managed products; use the defined publication/offline state for authorized withdrawals rather than deleting originals.
- Never publish unapproved material or private records, customer contact details, suppliers, pricing, orders, inquiries, database files, backups, AI logs, private workbench snapshots, unapproved assets, credentials or secrets. The public feed accepts only `code`, `name`, `category`, `identifier`, `description`, `specification`, and `markets` per product. Private inquiry exports must remain private. No fabricated live inquiries or unapproved messages.
- **Do not arbitrarily delete, empty, move or rename source files, public assets, historical content, managed records or Git history.** A specific user authorization is required for deletion or irreversible replacement. Use non-destructive status changes and retain original records/assets. Do not use force push, destructive reset or cleaning to bypass failures. The build may recreate its own generated `dist/` directory; do not commit it.
- Check the diff and preserve other people's changes. For code changes use an incremental branch based on `codex/unified-website`; run `node --test tests/*.test.mjs` and `node build.mjs`, confirm preview/PR checks and merge/publish only within user authorization. For content/feed updates check the relevant diff and build/tests. No empty commits. Do not modify hosting, domain, DNS, D1, Turnstile or authorization settings without user authorization.
- Verify successful Cloudflare deployment and the actual public pages, including product search, detail, links and inquiry entry point. A commit is not proof of deployment. Report verified results, exact files and commits, and any failure, unresolved item, or deletion (normally zero).
